## ADDED Requirements

### Requirement: Скил tasks
`skills/tasks/SKILL.md` SHALL описывать работу с задачами через CLI `tasks`: список, выбор,
просмотр задачи со скриншотами, взятие в работу, передача на ревью со ссылкой на pull request
или закрытие. Работа SHALL вестись в отдельной ветке `task/<номер>-<slug>` в репозитории проекта,
путь к которому берётся из `projects.yaml`. Результат SHALL проверяться тестами, для
iOS-проектов сборкой `xcodebuild`, до коммита.

#### Scenario: Пользователь просит взять задачу
- **GIVEN** `tasks` установлен, в репозитории задач есть задача 42 со статусом `todo`
- **WHEN** пользователь говорит «начни задачу 42»
- **THEN** агент читает задачу через `tasks show 42` и ставит `tasks start 42`
- **AND** работает в ветке `task/42-<slug>` в репозитории проекта из `projects.yaml`

#### Scenario: Модель без зрения
- **GIVEN** у задачи есть скриншоты с описаниями в тексте
- **WHEN** агент работает на модели без зрения
- **THEN** агент опирается на описания и не пытается открыть картинки

#### Scenario: Задача неясна
- **WHEN** текст задачи двусмысленный или противоречит коду
- **THEN** агент спрашивает пользователя до `tasks start`, а не угадывает

### Requirement: Скил публичный и раскладывается синхронизацией
Скил SHALL NOT содержать личных данных: имён, почты, названий закрытых репозиториев.
`sync-agents.py` SHALL раскладывать его в Claude Code, Codex и OpenCode как любой другой скил.

#### Scenario: Новый скил после sync
- **WHEN** запущен `sync-agents.py`
- **THEN** `tasks` виден в `~/.claude/skills` и `~/.agents/skills`

### Requirement: Агент не мержит и берёт одну задачу
Скил SHALL запрещать мерж pull request и push в основную ветку проекта. Агент SHALL вести
одну задачу за раз и SHALL NOT менять статус на `review` или `done`, пока тесты и сборка
не прошли.

#### Scenario: Задача доведена до PR
- **GIVEN** изменения закоммичены в ветку `task/42-<slug>`, тесты зелёные
- **WHEN** агент завершает работу
- **THEN** ветка запушена, открыт pull request, выполнено `tasks review 42 --pr <URL>`
- **AND** основная ветка проекта не изменилась

#### Scenario: Сборка не проходит
- **GIVEN** `xcodebuild` падает на ветке задачи
- **THEN** статус задачи остаётся `in_progress`, агент чинит или сообщает причину пользователю

### Requirement: Задачи доступны без бота и без CLI
Задачи SHALL храниться как обычные Markdown-файлы в git (`<проект>/NNNN-<slug>.md`,
скриншоты рядом в `attachments/`). Чтение и смена статуса SHALL оставаться возможными
вручную и через агента без бота, без установленного `tasks` и без конкретного провайдера
моделей. Скил SHALL описывать этот запасной путь.

#### Scenario: Бот выключен
- **GIVEN** бот и исполнитель остановлены
- **WHEN** пользователь просит «посмотри задачи»
- **THEN** агент читает список через `tasks list` из локального клона репозитория

#### Scenario: CLI не установлен
- **GIVEN** команды `tasks` нет в `PATH`
- **WHEN** пользователь просит «посмотри задачи»
- **THEN** агент делает `git pull` в репозитории задач и читает Markdown-файлы напрямую

#### Scenario: Нет сети
- **GIVEN** `git pull` не удался
- **THEN** CLI предупреждает и работает с локальной копией, а локальный коммит уходит при следующем push

### Requirement: CLI как внешняя зависимость
CLI `tasks` SHALL жить в проекте `task-inbox`, а не в ai-workspace. Он SHALL ставиться
командой `uv tool install --editable ~/Projects/ai/task-inbox` и лежать в `~/.local/bin/tasks`.
Отсутствие CLI SHALL NOT ломать `sync-agents.py` и остальные скилы.

#### Scenario: Свежий Mac
- **GIVEN** ai-workspace развёрнут, `task-inbox` не склонирован
- **WHEN** запускается `sync-agents.py`
- **THEN** скил `tasks` разложен, остальные скилы и агенты работают как раньше
