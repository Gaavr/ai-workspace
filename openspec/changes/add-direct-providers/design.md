# Design

## Имена
Прямая запись называется `direct/<провайдер LiteLLM>/<ID модели у провайдера>`:
`direct/zai/glm-5.3-flash`, `direct/deepseek/deepseek-v4-flash`.

Имя по маршруту LiteLLM (`deepseek/deepseek-v4-flash`) совпадает с ID той же модели
в каталоге OpenRouter. Две записи `model_list` с одним `model_name` LiteLLM считает одной
моделью и делит между ними запросы, а не переключается при ошибке. У z.ai совпадения нет
(`zai/` против `z-ai/`), но правило одно для всех прямых провайдеров: по префиксу видно,
что запрос идёт мимо OpenRouter.

Маршрут в `litellm_params.model` — `zai/glm-5.3-flash` и `deepseek/deepseek-v4-flash`,
из каталога LiteLLM 1.108.3. Перед включением сверить с `/models` у провайдера: у DeepSeek
есть и `deepseek-flash` — какой из них текущий, видно только с ключом.

## Цепочки
Ключ цепочки — ID модели каталога. `scripts/gateway-config.py` уже отдаёт общую цепочку
`openrouter/*` только моделям каталога без своей, так что своя цепочка её заменяет без правок
кода. Прямая запись своей цепочки не имеет: если упала и она, LiteLLM идёт к следующему
звену исходной цепочки — локальной модели.

## Ключи
Фильтр записей с пустым `api_key: os.environ/<VAR>` уже работает в шлюзе и в OpenCode
(требование «Модель без ключа выпадает»): прямая запись без ключа выпадает вместе со ссылками
на неё в `fallbacks`. Нового кода для этого не нужно.

## Лимиты
Лимиты прямой записи задаются вручную в `model_info`: каталог OpenRouter их не знает.
Значения — из таблицы LiteLLM 1.108.3 для самого провайдера (`zai/glm-5.3-flash`: 1048576/128000,
`deepseek/deepseek-v4-flash`: 1000000/393216), проверка — по `/models` провайдера (3.3).

## Риски
- OpenRouter может переименовать модель: ID каталога и ID у провайдера разъедутся, своя цепочка
  перестанет срабатывать. Ловит предупреждение `sync-agents.py` об уровне без модели
  и проверка 3.2.
- z.ai отдаёт разные эндпоинты для международного и китайского аккаунта. По умолчанию
  международный `api.z.ai`; китайский — через `api_base` у записи.
