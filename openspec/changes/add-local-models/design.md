# Design

## Где что лежит
```
/Volumes/Samsung T7 Shield/
├── AI Models/                      папка моделей LM Studio, как есть
│   ├── lmstudio-community/gpt-oss-20b-GGUF/gpt-oss-20b-MXFP4.gguf
│   └── Ollama/                     OLLAMA_MODELS
└── Apps/AI/ai-workspace-kit/
    ├── runtime/ollama/<версия>/    распакованный ollama-darwin.tgz, запускается отсюда
    └── installers/                 ollama-darwin.tgz, LM-Studio-*.dmg
```
Путь к SSD и к комплекту — переменные `AI_SSD` и `AI_KIT` в `.env` с этими значениями
по умолчанию: имя тома может поменяться.

## Импорт gpt-oss-20b
`Modelfile` с `FROM <путь к gguf>`, `PARAMETER num_ctx 16384`, `ollama create gpt-oss-20b-ssd`.
Ollama копирует веса в своё хранилище — ещё ~12 ГБ на SSD, место есть (свободно ~750 ГБ).

Риск: у gpt-oss свой формат сообщений (harmony). Если импортированная модель не вызывает
инструменты, берём официальную сборку `ollama pull gpt-oss:20b` (~13 ГБ) — это скачивание,
только с согласия владельца.

## Память
16 ГБ на M4, Metal по умолчанию отдаёт видеопамяти ~10–11 ГБ. Веса 12 ГБ целиком на GPU
не влезут: часть слоёв уйдёт на CPU, скорость упадёт. Для теста это приемлемо. Поднять
лимит можно `sysctl iogpu.wired_limit_mb` — это системная настройка, её меняет владелец сам.
`num_ctx 16384`: системный промпт OpenCode с агентами занимает ~10 тыс. токенов,
меньше контекста не хватит.

## Без SSD
`ollama.sh start` проверяет том. Нет тома — печатает предупреждение и выходит без ошибки,
шлюз стартует без локального рантайма. Запрос на `gpt-oss-coder-local` тогда кончается
понятной ошибкой соединения в конце цепочки.

## LM Studio
Папка моделей задаётся в настройках приложения (My Models → путь) на `AI Models`.
Сервер поднимается вручную: `lms server start` (порт 1234). Перед этим Ollama-модель
выгрузить: `ollama stop gpt-oss-20b-ssd`.
