# Инструкции проекта для агентов

## Когда применять

В проекте нет AGENTS.md (режим «создать») или он есть, но раздут, устарел, дублирует код
или разбросан по файлам разных инструментов (режим «переделать»).

Не применять для глобальных личных инструкций (`~/.claude/CLAUDE.md` и т. п.) и для
написания скилов и агентов — это отдельные задачи.

## Целевая раскладка

```
AGENTS.md          источник правды, читают все агенты, бюджет ниже
CLAUDE.md          одна строка @AGENTS.md (+ то, что нужно только Claude)
docs/ai/rules.md   подробные правила: архитектура, язык и стиль, запреты с причинами
docs/ai/<тема>.md  по необходимости: БД, деплой, тесты — то, что нужно не в каждой задаче
<папка>/AGENTS.md  локальные правила подсистемы в монорепо
```

Шаблоны: [templates/AGENTS.md](templates/AGENTS.md), [templates/rules.md](templates/rules.md).
Комментарии `<!-- -->` в шаблонах — подсказки, в итоговых файлах их не оставляй.

Как распределять содержимое:
- **AGENTS.md** — то, что нужно в каждой сессии: назначение, команды, карта, критичные запреты,
  проверка, ссылки. Ссылка только с условием: «Перед X прочитай Y». Голый список ссылок агенты
  пропускают.
- **rules.md** — то, что нужно, когда пишешь код. AGENTS.md требует прочитать его перед первой
  правкой, поэтому он фактически грузится при любой работе с кодом, но не при вопросах.
- **Тематические файлы** — то, что нужно редко.
- **README.md** — файл для человека, агент его каждый раз не читает. Установку окружения с нуля
  в AGENTS.md не копируй, а сошлись с условием: «Окружение не поднимается — раздел „Быстрый
  старт" в README.md». Пишет и чинит README скил `readme`.
- Запрет, нарушение которого необратимо (прод, миграции, секреты, force push), — в AGENTS.md,
  не в rules.md: файл по ссылке агент может не открыть.
- Каждое правило живёт в одном месте. Не копируй между файлами — ссылайся.
- `@файл` понимает только Claude Code и грузит его всегда, токенов это не экономит. Для остальных
  инструментов — только ссылки текстом.

## Бюджет

AGENTS.md грузится в каждую сессию, и с ростом числа правил агент выполняет каждое хуже.
Бюджет — жёсткий потолок, а не цель: короче — лучше.

| Файл / блок | Цель | Потолок |
|---|---|---|
| **AGENTS.md целиком** | 60–80 строк | 150 строк и 8 КБ |
| Назначение | 1–3 предложения | — |
| Команды | 4–6 строк | 10 |
| Архитектура | 3–7 строк | 7 |
| Запреты | 3–5 пунктов | 7 |
| Проверка | 2–4 шага | 5 |
| Подробнее (ссылки) | 3–6 | 10 |
| `<папка>/AGENTS.md` | 10–30 строк | 50 |
| rules.md, тематический файл | — | 300 строк |
| `ВАЖНО` / `MUST` на весь AGENTS.md | 0–2 | 3 |

Блок вышел за потолок — переноси лишнее по таблице исходов из шага 4б, а не ужимай
формулировки до телеграфа. В режиме «переделать» действует правило «одно вошло — одно вышло»:
новое правило в полном файле появляется, только если другое перенесено или удалено.

Codex по умолчанию читает из AGENTS.md только первые 32 КБ (`project_doc_max_bytes`),
остальное обрезает молча. Потолок в 8 КБ держит большой запас.

## Порядок

### 1. Собери факты из проекта

Прочитай: README, манифесты (package.json, build.gradle, pyproject, Makefile, Package.swift),
CI-конфиги, линтеры и форматтеры, структуру верхних двух уровней папок, последние 30 коммитов
(формат сообщений), существующие файлы инструкций: AGENTS.md, CLAUDE.md, CLAUDE.local.md,
GEMINI.md, gigacode.md, .cursorrules, .cursor/rules/, .github/copilot-instructions.md,
.claude/rules/.

### 2. Проверь команды

Запусти сборку, линтер и тесты, найди, как запускается один тест. В файл попадают только
команды, которые отработали. Команда требует окружения (docker, ключи, VPN) — напиши это рядом.

### 3. Спроси человека о том, чего нет в коде

Одним сообщением, только то, что не нашёл сам:
- для чего система и кто ей пользуется;
- что агентам нельзя делать — что уже ломали или чего боитесь;
- что значит «задача сделана» помимо зелёных тестов;
- язык ответов, комментариев и коммитов, если не очевиден из истории.

### 4а. Режим «создать»

Заполни шаблоны фактами из шагов 1–3. Пустой блок удали — лучше нет раздела, чем заглушка.

### 4б. Режим «переделать»

Разбери каждое правило существующих файлов и отнеси к одному из исходов:

| Исход | Когда |
|---|---|
| оставить в AGENTS.md | нужно в каждой сессии и не выводится из кода |
| в rules.md | нужно при написании кода |
| в docs/ai/<тема>.md | нужно в редких задачах |
| в README.md | адресовано человеку: онбординг, установка с нуля, история, контакты |
| удалить | выводится из кода, проверяется линтером, общий совет («пиши чисто»), устарело или противоречит коду |
| в хук или CI | должно выполняться всегда без исключений |
| в скил | это процедура из нескольких шагов («как выпустить релиз») |

Покажи человеку таблицу «правило → исход» **до** правок. Удаление — только после согласия.
Правило, которое противоречит коду, не удаляй молча: спроси, что верно — правило или код.

Файлы других инструментов (gigacode.md, GEMINI.md, .cursorrules) с тем же смыслом сведи
в AGENTS.md, а сами файлы замени ссылкой на него или симлинком. Что поддерживает конкретный
инструмент, проверь по его документации, не угадывай.

### 5. Предложи агентов под повторяющиеся задачи

Если в проекте видны отдельные типы работы (BDD-сценарии, UI-тесты, миграции БД, ревью),
перечисли кандидатов: роль, когда вызывать, какие файлы трогает, чего не делает.
Не создавай их без отдельной просьбы.

## Чего не делать

- Не описывай структуру классов, зависимости, файл за файлом — агент прочитает код сам.
- Не пересказывай README и не отправляй агента читать его без условия.
- Не пиши то, что исправит форматтер.
- Не добавляй правила «на всякий случай». Правило появляется, когда агент ошибся на этом дважды.
- Не оставляй ссылку на несуществующий файл и ссылку без условия.

## Проверка результата

- Каждый файл и блок укладывается в бюджет: `wc -l -c AGENTS.md docs/ai/*.md`. Покажи
  человеку итоговые цифры рядом с потолками.
- Каждая команда из файла запускалась в шаге 2.
- Каждая ссылка ведёт на существующий файл и начинается с условия.
- Ни одно правило не встречается в двух файлах.
- Сделай `grep` по ключевым словам каждого запрета и конвенции: код им не противоречит.
- Покажи итоговые файлы и сводку: что добавлено, что перенесено куда, что удалено и почему.
