# README проекта

## Когда применять

В проекте нет README, он устарел, раздут или не помогает новому человеку запустить проект.

Не применять для инструкций агентам (AGENTS.md, rules.md — скил `agents-md`), для справочника
по API и для подробной документации — она живёт в `docs/`, README на неё ссылается.

## Для кого файл

README читает человек: новый разработчик, пользователь, тот, кто наткнулся на репозиторий.
Агенты его каждый раз не читают, и AGENTS.md не должен отправлять их в README без условия.

Разделение с AGENTS.md:

| README | AGENTS.md |
|---|---|
| что это и зачем | только назначение одной строкой |
| установка и первый запуск с нуля | ежедневные команды: тесты, один тест, линтер |
| примеры использования, скриншоты | — |
| настройка, переменные окружения | запреты и проверка результата |
| как участвовать, контакты, лицензия | ссылки на rules.md и тематические файлы |

Одна информация — в одном файле. Установку окружения AGENTS.md не копирует, а ссылается:
«Окружение не поднимается — раздел „Быстрый старт" в README.md».

## Порядок

### 1. Определи тип проекта

Приложение, сервис, библиотека, CLI или внутренний инструмент. От типа зависит главный блок:
у приложения — скриншот и запуск, у библиотеки — установка и пример кода, у сервиса — как
поднять локально и где он развёрнут, у CLI — пример вызова с выводом.

### 2. Собери факты

Прочитай манифесты, `.env.example`, docker-compose, CI, `docs/`, существующий README.
Спроси человека одним сообщением о том, чего нет в коде: для кого система, статус (прототип,
продакшен, заморожен), владельцы и контакты, где задачи.

### 3. Проверь быстрый старт

Пройди шаги установки и запуска сам, как новичок: в чистом клоне или worktree, по порядку,
не пользуясь тем, что уже стоит у тебя. Шаг не сработал — исправь README или сообщи о проблеме
в проекте. Шаг требует того, что нельзя проверить (доступы, VPN), — пометь это в тексте.

### 4. Напиши по шаблону

Шаблон: [templates/README.md](templates/README.md). Блок, которому нечего сказать, удали.
В режиме «переделать» покажи человеку, что уходит из README и куда (в `docs/`, в AGENTS.md,
в никуда), до правок.

## Правила текста

- Первый экран отвечает на три вопроса: что это, зачем, как запустить.
- Команды — готовые к копированию, по одной на блок, без `$` и без вывода внутри блока.
- Требования с версиями: «Node 20+», а не «Node».
- Пример вывода или скриншот показывает, что запуск удался.
- Подробности ссылкой на `docs/`, не пересказом.
- Без истории проекта, списка изменений (для этого CHANGELOG.md) и стены бейджей.
- Без структуры каждого файла — две-пять строк о верхних папках, если она неочевидна.

## Чего не делать

- Не пиши в README правила для агентов и стиль кода — это AGENTS.md и rules.md.
- Не вставляй команды, которые не запускал.
- Не оставляй заглушки «TODO: описать» — удали блок.
- Не придумывай возможности, которых нет в коде.

## Проверка результата

- Быстрый старт пройден в чистом окружении, или в отчёте сказано, какой шаг не проверен и почему.
- Все ссылки ведут на существующие файлы.
- Сведения из README не повторяются в AGENTS.md.
- Покажи итоговый README и сводку: что добавлено, что убрано и куда перенесено.
