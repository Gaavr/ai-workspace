# Проверка репозитория перед публикацией

## Когда применять

Репозиторий переводят из приватного в публичный. Готовят первый push в открытый репозиторий. Хотят убедиться, что ключи не попали в коммиты.

Не нужен для проверки текущих незакоммиченных правок — для этого хватает `git status`.

## Порядок

1. Выведи отслеживаемые файлы: `git ls-files`. Проверь, нет ли `.env`, `data/`, каталогов с суффиксом `.local`.
2. Найди секреты во всей истории, а не только в текущих файлах:
   `git log --all -p | grep -cE "sk-or-v1-|sk-ant-api|sk-proj-|ghp_|github_pat_|eyJhbGciOi|AKIA[0-9A-Z]{16}|-----BEGIN.*PRIVATE KEY"`
3. Если счётчик больше нуля, найди коммиты: `git log --all --oneline -S "<префикс>"`.
4. Проверь присвоения ключей в конфигах:
   `git ls-files -z | xargs -0 grep -nE "(api[_-]?key|token|secret|password)\s*[:=]\s*['\"]?[A-Za-z0-9_\-]{20,}"`
5. Проверь личные данные — почту, локальные адреса, имена внутренних хостов:
   `git ls-files -z | xargs -0 grep -lE "[a-zA-Z0-9._%+-]+@[a-zA-Z0-9.-]+\.[a-z]{2,}|192\.168\.[0-9]+\.[0-9]+"`
6. Посмотри, что уйдёт следующим коммитом: `git status --short` и `git diff --cached`.
7. Собери отчёт по форме из раздела «Проверка результата».

## Чего не делать

- Не выводи найденные ключи в ответ. Называй файл, строку и тип секрета.
- Не считай `.gitignore` доказательством: он не влияет на уже отслеживаемые файлы и на историю.
- Не проверяй только рабочую копию. Секреты остаются в старых коммитах после удаления файла.
- Не предлагай `git filter-repo` первым шагом. Сначала отзыв ключа у провайдера, переписывание истории — потом.
- Не считай находкой ссылки на переменные окружения (`os.environ/KEY`) и плейсхолдеры (`<your-key>`).

## Проверка результата

Отчёт из четырёх строк:

```
Отслеживается лишнего: нет | список файлов
Секреты в истории:     нет | N совпадений в M коммитах
Ключи в конфигах:      нет | файл:строка
Личные данные:         нет | список файлов
```

Затем вывод: публиковать можно, или что сделать до публикации.

Если секрет найден в истории — первым действием отозвать ключ у провайдера. Ключ мог быть уже прочитан, отзыв обесценивает утечку независимо от чистки истории.
