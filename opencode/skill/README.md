# Скиллы

Переиспользуемые процедуры для агентов OpenCode.

## Структура

```
skill/имя-скилла/SKILL.md
```

Имя папки совпадает с полем `name` в шапке файла.

## Публичные и приватные

| Путь | В git | Для чего |
|---|---|---|
| `opencode/skill/` | да | процедуры без личных деталей |
| `opencode/skill.local/` | нет | рабочий контекст, внутренние договорённости |

Обе подключены симлинками в `~/.config/opencode/skill/` как `public` и `private`.
OpenCode читает вложенные папки, поэтому видит скиллы из обеих.

## Формат

```markdown
---
name: имя-совпадает-с-папкой
description: Что делает и когда применять
---
Тело инструкции.
```

## Главное про description

Модель постоянно держит в контексте только описание. Тело подгружает,
когда решит, что скилл подходит. Значит в описании должны быть триггеры —
слова, которые встретятся в реальном запросе.

| Плохо | Хорошо |
|---|---|
| `Про тесты` | `Использовать когда нужно запустить тесты или разобрать падение` |
| `Стиль кода` | `Использовать перед написанием нового Swift-файла` |
| `Работа с git` | `Использовать при создании веток, коммитов и PR` |

## Что класть внутрь

Процедуру, а не рассуждение: что сделать, в каком порядке, чего не делать.
Скилл заменяет объяснение, которое иначе пришлось бы давать каждый раз.

Длиннее полутора страниц — скорее всего это два скилла.

## Создать новый

```bash
cp -R opencode/skill/_template opencode/skill/новое-имя
open -e opencode/skill/новое-имя/SKILL.md
```

Не забудь поменять `name` в шапке на имя папки.

## Применить

Перезапустить OpenCode через Cmd+Q — скиллы читаются при старте.

## Проверить

Спросить у агента: «Какие скиллы тебе доступны?»
